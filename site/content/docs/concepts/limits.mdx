---
title: Limits
description: The conditions in which the library cannot keep the context, and what to do in each condition.
order: 14
---

The library keeps the context in transformed code and in the callbacks of the patched APIs. In the conditions on this page, it cannot keep the context. In each of these conditions, the code gets the root context, not the context of a different operation (rule C7).

## Code that the build does not transform

A native `await` continues the function without a step of the runtime. Thus, after a native `await`, the function gets the root context. This applies to these modules:

- Dependencies that the build does not give to Babel, for example a dependency that a Babel configuration excludes.
- Scripts from other servers, for example a script from a content delivery network.
- Code of browser extensions.

<Callout type="caution" title="Transform the dependencies">
  Use the Vite plugin with its default `include`, or configure Babel to transform `node_modules`. Else, a callback that a dependency starts after a native `await` gets no value.
</Callout>

The [context timeline](/explore/timeline) has a scenario with an untransformed dependency.

## Callbacks of APIs that the runtime does not patch

The [patched APIs](/docs/concepts/patched-apis) page gives the list of patched APIs. A callback of a different API gets the root context. Use a snapshot for such a callback:

```ts
import { AsyncContext } from "async-browser-context";

legacyLibrary.onDone(AsyncContext.Snapshot.wrap(() => {
    console.log(requestId.get()); // the context of the wrap() use
}));
```

## Code in eval() and new Function()

The build cannot transform text that the code compiles at runtime. Async functions in `eval()` and `new Function()` stay native.

## Workers, iframes and other realms

Each realm has its own global object and its own store. A context does not go from a page to a worker or to an iframe. Send the values in the messages.

## Other patches of Promise.prototype.then

zone.js and other libraries also patch `Promise.prototype.then`. The library does not operate together with them.

<Callout type="caution" title="zone.js">
  Do not use this library and zone.js in the same page. The two libraries patch the same functions with different rules.
</Callout>

## Node.js

On Node.js, the native `AsyncLocalStorage` keeps the context in all code, also in code that Babel does not transform. The limits on this page do not apply there, except the rule for native generators (rule C5).
